# APPLICATION v2 — 質問型の入口・Lite継続クラス

2026-11-11 時点の PR #178 の初回接続範囲。既存 APPLICATION を置き換えず、下書き保存・表示・再編集まで実装する。

## 基本原則

- 入口は4つ（イベント・予約・販売・クラス）。入口はユーザーのためであり、内部のデータや権限は共通化する。
- 質問に順番に回答し、案内パネルを自動構成。編集できるのは順番と自由記述。価格・日時・定員は質問側から変更する。
- 日時は日付、開始時刻、所要時間（分）、タイムゾーンの独立した値。自由文で日時を解析しない。
- 追加質問の回答内容は、正式価格・定員・予約可否の判定に使用しない。
- APPLICATION、CALENDAR、FORM、Square の既存の業務処理を維持する。

## 現時点で接続した機能

- `/application-v2-test` : 4つの入口、質問、表示順変更、参加者プレビュー
- `/api/application/manage` : 質問回答を APPLICATION の下書きとして保存・更新
- `definition.wizard` : 作成目的、日時、場所、表示順等の案内メタデータ。予約・決済の正本には用いない
- 公開 APPLICATION レンダラー : `definition.wizard` の案内パネルを会員・ゲストに表示
- STUDIO の APPLICATION 管理 : 質問型で保存された APPLICATION を再び質問画面で編集
- Organizer 以上で追加の質問を Builder FIELD として表示・回答収集。Free / Plus Lite は追加質問不可
- Lite 継続クラス : 同じ受講者の最初の APPLICATION 申込を在籍の基礎とする。開催回ごとに新しい申込を作らない
- Lite 継続クラス : 有料でも有効在籍の上限を10名にする。主催者が退会処理すると申込履歴と支払記録を保持しつつ、新しい在籍枠が空く

## 大切な制限

- 下書き保存でPAGEは自動生成されず、公開もされない。主催者が既存の STUDIO から作品へ APPLICATION を設置する
- Liteの日程は案内でありCALENDARの開催回を生成しない。都度予約、空き枠の自動確保、出欠、振替、月謝は扱わない
- 予約入口は予約**希望**受付にとどまり、確定日時は主催者が連絡する
- Squareに接続済みの主催者は既存の単一APPLICATION決済を使用できるが、一括決済・自動返金は未対応
- URL限定の希望を選んでもそれだけでは閲覧制御にならない。作品の公開範囲が正本
- 複数商品・複数人の同時確保・一括決済はまだ未対応
- 追加質問は、Liteでは作成不可。Organizerでは Builder FIELD を使うが条件判定には利用しない
- 継続クラスの退会は主催者のみ実行。支払済の場合も返金は自動実行せず、主催者が個別対応する
- 実ブラウザーでの申込・Square決済のE2E検証後に本番反映を判断する

## 本番前の必須確認

1. Free / PlusでLiteクラスを作り、登録10名で受付上限となること
2. 10名のうち1名を退会し、履歴を保持しつつ11人目の新規申込が可能になること
3. 再編集しても表示順・案内・日時・料金が一致すること
4. 既存のAPPLICATION（wizardなし）に影響しないこと
5. 登録ユーザーとゲストの申込フロー、送信メール、本人確認に回帰がないこと
6. Squareの少額実決済と返金の運営手順を確認すること
