# ログインリンクの期限と復帰

2026-10-14 JST。利用者合意：メールリンクは発行から10分・1回限り。ログイン後のセッション継続時間は変更しない。PKCEへ切り替えず、リンクを開いたブラウザーで利用を続ける。

## サーバー設定（コードの公開だけでは反映されない）

- Supabase Authentication の Email provider 設定にある `Email OTP Expiration` を **600秒** に設定する。Management API の対応する設定名は `mailer_otp_exp`。
- 対象を必ず確認する。本番：`gqlwepkldjxqvlfxsoel`、隔離テスト：`odrpsdmsaeunofjyjdfw`。個別設定であり、Previewから本番へ自動反映されない。
- JWT expiry / session timeout / SMTP再送間隔ではない。この作業ではそれらを変更しない。
- Email OTPとMagic Linkは共通の期限設定。会員登録の確認メールを含むメール認証経路も確認する。
- 現在の連携にはAuth configの読み書きツールがない。**この文書の追加時点では600秒の設定は未反映・未検証。** 管理画面で既存値を控え、保存後に600秒を読み戻す。秘密鍵・メールリンク・認証トークンは記録しない。
- ブラウザーのタイマーで期限を代用しない。文言だけで10分を保証しないため、画面では有効期限の存在と再申請の方法を案内する。

## 少人数での実機確認

1. 隔離テスト側で600秒を保存し、新しいリンクを発行する。10分以内に開いてログインできることを確認する。
2. 別の新しいリンクを未使用のまま10分超待ち、ログインできないことと再申請導線を確認する。待機に使った時間を記録し、長時間のブロッキング処理はしない。
3. 使用済みリンクで新しいログインが成立しないことを確認する。有効な既存セッションが残っていても、そのアカウントで失敗したリンクの処理を続けない。
4. LINE内で申請してメールのリンクをSafari等で開いた場合、リンクを開いたブラウザーで操作を続けられることを確認する。元の未ログイン画面ではLIVE会場に入れない。
5. 会員登録後の戻り先、APPLICATIONゲスト履歴の紐付け、既存ログインの継続を確認する。
6. 本番反映時にも600秒の設定を読み戻し、正常ログインを確認する。

自動確認：`node scripts/test-login-links.cjs`（Reactと偽AuthによるUI確認）。実メールの期限やブラウザー間通信を検証したことにはならない。

## 既存STAGE PRとの統合

この変更はmainからの独立修正。#135/#136にも `CppLiveEventRoom` の認証処理があるため、統合時はSTAGE側の進行同期・権限変更時の破棄を保持し、未ログイン案内と戻り先付きリンクを取り込む。古い会場コンポーネントで上書きしない。
