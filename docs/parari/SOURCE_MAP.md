## Work creation, editing and reading

| Purpose | Active entry and implementation |
| --- | --- |
| Creation | `/editor/new`, `/editor/quick` |
| Editing | `/editor-v2/[id]` → `mvp/PagePanelComposer` or `mvp/WebPageComposer` |
| Public work reader | `/p/[id]`, `/access/[key]`, `/[username]/[workSlug]`, `/[username]/[workSlug]/[pageSlug]` → `PublicViewerShell` |
| Old PAGE creation/edit URLs | `/[username]/pages/new` redirects to `/editor/new`; `/[username]/pages/[workId]/edit` redirects to `/editor-v2/[id]` |
| Old PAGE reading URL | `/[username]/pages/[workId]/view` carries username and work ID to the shared server authorization check, then uses `PublicViewerShell` |
| Reader format dispatch | `PublicWorkLoader` → `/api/works/read` → `PublicViewerShell` → `viewer-v2/ParariViewer`; `buildViewerDocument` derives its reading sheets from existing SSOT |
| Shared reading content | `reader/ReaderBodyPanelRenderer` and `viewer-v2/ViewerTextBlock`; `ReaderToolbar` owns the shared menu and `readerProgress` handles per-work reading position |
| Editor/CPP content rendering | `mvp/PageBodyPanelRenderer` is used by editor previews and CPP profiles; it is still active |

`ParariViewer` is the only reading controller. BOOK keeps cover/chapter/TOC composition through `book/buildBookSheets`; PAGE content stays intact as a reading sheet; WEB selects its page through `web/webSsot` and adds site chrome through `web/WebPageFrame`. Display mode, font, dictionary, ruby and reading-position reset all use one menu. Complex panels remain intact when they cannot be split safely. The three former viewers and `ReaderSettingsBar` are retired; do not restore alternate reading controllers. Existing BOOK progress is read as a compatibility fallback and new progress is keyed by work ID (and WEB page slug).

Despite its directory name, the retained `mvp` code is used in production. Do not delete a component based on its name. Old standalone `PageEditor`, `PagePublicView`, development routes, unused components and old patchers have been removed. Do not restore them as alternate active paths.

## Dictionary and data

The runtime English dictionary is the database table `parari_english_dictionary`, accessed through `/api/english/dictionary`. Administration uses `/my/operations/dictionary` and `/api/internal/english-dictionary`.

Editor tools are one optional **英語教材支援** menu. Enable it under `/my/settings#english-authoring`; the account preference `english_authoring_enabled` in Auth user metadata defaults to OFF. This preference never grants an entitlement. `/api/english/authoring` verifies the authenticated editor's current `getUserPlanAccess` (Plus/Organizer/Host/Pro, retaining the existing monitor override) and opt-in before querying. Billing/profile errors fail closed. Public reader dictionary access remains independent.

`EnglishAuthoringProvider` scopes all editor dictionary menus and support previews, including nested panels. `RichTextField` uses real lookup results and display-only CSS highlights through `DictionaryHighlightPlugin`. With authoring enabled, clicking a word during editing opens a fixed dictionary result card without changing the caret or body; manual selected-word lookup also remains available. Marks default to visible within that opt-in: gray dotted underlines for registered words, red backgrounds for confirmed missing words. Editor previews and the public reader share this status rule and mark classes. Loading, failed and unqueried words are not marked as missing. `EnglishAuthoringMenu` is one **…** button beside **完了**; the Lexical toolbar renders it into that header via a portal so selection-based lookup stays connected to the same editor. It remains accessible when the body loses focus. Long-text fallback uses the same header menu without Lexical-only selection tools. The old always-unregistered stub and separate “読む支援” menu are retired. TEXT reading-support attributes keep their existing serialization and are never cleared by opt-out or downgrade. Their current scope is the editor; the public unified viewer still uses reader menu choices.

The **英検級で色分け** switch uses the existing `eiken` attribute to show word backgrounds during Lexical editing and in confirmation: 1級 orange, 準1級 light orange, 2級 amber, 準2級 yellow, and 3〜5級 one pale green. Unknown grades have no grade background. The palette and labeled legend share `english/eikenBackground.ts`; dictionary marks remain independent. Red always means confirmed missing, not difficulty. Inline translations, superscript grade labels and their annotation threshold UI are retired. Legacy `notes` / `noteFrom` attributes still round-trip without rendering inline notes. The public reader retains its settings and gains the same red missing-word backgrounds.

`test:english-authoring` checks real route handlers, shared plan rules, React settings, Lexical selection and direct word clicks, caret preservation, all five grade backgrounds in editing/confirmation, red missing-word backgrounds, independent color/mark toggles, the header menu location and focus/selection/dismissal behavior, no inline notes, loading/failure/cancellation, opt-out/downgrade and preservation of saved TEXT content/attributes against simulated Auth/database responses and DOM geometry. It does not claim signed-in production or visual browser verification.

The old CSV master was already removed in PR #94. Its remaining comparison/batch scripts and 22 derived CSV reports were retired in this cleanup. The three original input lists (`center_exam_words.csv`, `中学英単語.csv`, `高校英単語.csv`) remain as source material for future dictionary coverage work. They are not runtime masters; database coverage of every source word has not been assumed. Database migrations and database contents are unchanged.

## Paid reading (2026-10-08)

BOOK/PAGE authors insert one `[PAYWALL]` structural line between content blocks. `commerce_work_access` associates the work with an existing one-time product for that work and/or a monthly product owned by the same seller. The same monthly product can cover several works. SSOT alone owns the boundary; prices and entitlements remain in commerce tables. WEB boundary insertion is rejected because WEB pages do not form one reading sequence. Removing the marker makes the work free again; changing plan never deletes it. Lexical has no PAYWALL node.

All public reader URLs now obtain transient display projections from `/api/works/read`. The server authenticates the bearer token and checks ownership, assigned editing, existing work purchases, membership visibility, and subscription paid-through time. It cuts the source before composition for readers without rights: paid page titles, TOC entries, images and other later panels never enter their response. Orphan and malformed boundaries fail closed. `buildPublicReaderDocument` runs the existing BOOK/PAGE/WEB parsers and removes source containers before sending display fields. `ParariViewer` remains the only reading controller, including nested panels, physical pagination, dictionary/ruby and saved progress. Application delivery uses the same display projection after its existing entitlement check.

Restrictive database policies block direct paid source reads by anonymous users and nonauthors, including purchasers. `parari_public_works` is an intentionally definer-owned, security-barrier catalog view: it explicitly filters visible, undeleted works and returns NULL content for paid works. It preserves public listings without giving clients source access. Purchase/subscription history uses `/api/commerce/library`, which returns only authorized titles and product information. Membership preview and shelf APIs also omit paid source.

Square invoice reconciliation verifies merchant, latest invoice, subscription ID, PAID status, exact settled amount/currency, and the provider billing period/timezone. `charged_through_date` alone means invoiced, not paid, and never grants rights. The exclusive paid-through timestamp is updated atomically without adding another month on retries. One-time purchase completion and refund handling are atomic and idempotent; a delayed payment cannot restore a fully refunded or manually revoked entitlement. Cancellation and failed renewal retain earlier paid time; confirmed refund of the relevant invoice clears it and records its invoice ID to reject an already in-flight paid response. The Square webhook should include `invoice.payment_made`, `invoice.updated`, `invoice.refunded`, `invoice.scheduled_charge_failed`, `subscription.created`, and `subscription.updated`, alongside existing payment/refund events. Existing seller tier rules remain: monthly sales require Organizer or above. Reader rights do not depend on the reader's PARARI plan.

Checkout accepts only internal return paths. The buy page sends unauthenticated readers through the existing login/callback return flow, then checks server entitlements after Square redirects. A redirect parameter never grants access. Purchasers can return to the same work; delayed payment notification has an explicit retry action. No real payment is initiated by the automated tests.

Verification: `test:paid-reading` runs real reader/settings/library/status and signed webhook handlers against deterministic Auth/DB/Square adapters. It covers free/paid/private/unlisted/owner/expiry/refund/failure, username ownership, boundary round trips, nested/WEB source removal, safe returns and Japan/DST billing dates. `test:unified-viewer` now exercises server-prepared documents in the real React DOM reader. Database policies were separately verified on Supabase with an entirely rolled-back fixture: anonymous/nonowner raw reads denied, author read retained, safe catalog retained, client mapping/grant writes denied. SQL migrations 20261008010316, 20261008010716, 20261008011036 and 20261008011549 are applied.
