# CLASS 管理画面 UI 正本 — 2026-11-28
2026-11-28にユーザーが選んだ4パネルの入口を今後の実装基準とする。
- 設計：事業・コース・クラス。既存の事業ツリー、初回作成ウィザード、コース内容・料金、開催枠。
- 募集：入会・イベント。既存の公開ページ、入会フロー、イベント、講習会、16問の改善。
- 運営：生徒・出欠・開催予定。既存の入会対応、名簿、欠席連絡、開催予定、イベント・講習会受付（募集と共通コンポーネント）。
- 会計：月謝・入金・売上。コース料金の参照、既存の差額入金確認・記録、販売・売上への導線。未実装の月次請求・集計は準備中と明記。
- 事業設定・契約・利用枠：事業名・呼称、選択事業に固定したCLASS B契約、販売・決済への導線。
ホームは4パネル2列、緑の線画アイコン、操作文字16px・タップ44px以上を目安。事業の選択は共通。下層ではCLASSホームへの戻り導線。旧5タブと開設/運営切替を初期入口から撤去。従来の保存API・権限・SSOTを変更しない。会計の月謝自動請求、一般販売、QR受付の本番開放はこのUI改修で有効化しない。
プレビューは実データと接続する可能性があるため画面・導線の確認に限定。実データを保存・公開・入金操作しない。既存データの変更・削除、DBマイグレーション、本番デプロイなし。

## 2026-11-28 利用者の仕事による再整理（承認済み）
- 新規事業の開設、既存事業の商品構成の変更、日常運営を区別。事業一覧は独立画面とし、選択後は事業名と「戻る」のみ表示。1事業でも一覧から選ぶ。新規作成後は設計に進む。
- 提供サービスは継続コース、短期講習会（複数開催回）、イベントの3種。クラスはコース内の開催枠。構成図に実データを表示し、作成ボタン4つは色付き図の外に置く。
- コース単体の作成と開催枠の追加を分離。コース未登録時のみ従来の初回クラス作成ガイドを使用し、複数コースがある場合は追加先を選択する。
- イベント・講習会は設計で下書き保存、募集で公開・受付終了・告知、運営で参加者と出欠を管理。同じAPIと既存コンポーネントを使用。受付終了した企画は構成図の履歴に表示。受付終了とサービス廃止は同一ではない。
- コース・クラスの廃止（契約・在籍者・振替・予約との整合を含む）は未実装。削除機能を仮実装しない。

## 共通移動と呼称設定（2026-11-28）
- CLASSホームの4パネルを維持し、各下層画面に設計・募集・運営・会計の共通タブを常設する。
- 事業設定でコース、クラス、短期講習会、イベントの表示名を設定可能とする。既存の役割呼称とは独立し、事業単位の既存JSONB設定に service_ 接頭辞で保存する。未設定は標準名称。内部分類・契約・上限・料金は不変。今回の反映範囲は管理ホーム・構成図・主要作成ボタン・募集と運営の入口・コースとイベント編集の主要ラベル。旧画面、公開ページ、メール、すべての説明文への適用は今後の課題。旧本番の役割呼称保存処理は新キーを保持しないため、プレビュー中は実事業への保存を行わない。

## 事業の形態と申込単位（2026-11-28 承認済み）
- 事業が提供するサービスは継続コース・短期講習会・イベントから複数選択し、中心となるサービスを一つ指定。変更は設計案であり、既存のサービスを閉鎖・削除・非公開にしない。
- 事業への入会制度は任意。事業会員と個別サービス参加資格は独立したデータ・手続きとして将来実装する。入会者限定、一般参加可能などは各サービスで決定する。サービス間の前提条件やフロー連結は現段階の対象外。
- 募集の入口は個別サービス一覧、事業の募集ページ、必要な場合の事業共通設定。事業ページの構成案は主サービス優先、入会案内は入会制度を選んだ場合のみ。既存の公開PAGEを自動編集・公開しない。
- 今回のプレビュー実装では事業形態をブラウザのセッションに保存して設計・募集・運営・会計の表示を変更。既存レコードを持つサービス種は参照可能。コースの個別募集は既存 offer API の対象開催枠に限定した UI から確認できる。既存の複数コース共通 offer を自動分割しない。イベント・講習会は既存の個別受付を再利用。
- 未実装：独立した事業会員台帳、会員資格と個別参加権限のサーバー側照合、コース単位の規約・支払い・予約枠・メール・承認設定の分離、公開募集PAGEへの自動パネル構成。この設計案だけで会員制・契約・権限が変わったとは扱わない。

## 設計図と募集の工程図（承認済み 2026-11-28）
- 設計はサービス内容、料金、開催枠、参加資格を決める場所。募集は事業入会と各サービスの参加までの手続きを独立した工程図にする。工程を押すと下の編集欄が変わる。
- 募集の図は事業への入会（制度ありの場合のみ）と各サービスの行。募集PAGE→必要な予約・説明会→申込→必要なテスト・確認・同意→開催枠選択（コースのみ）→事前決済（有料の場合）→確定。現地払いは確定後の当日手順として明示。
- 設計の料金・開催枠を参照し、募集で料金を再入力しない。参加資格の変更入口は設計。新工程の追加や削除は必要な設定に応じて反映し、自由な並べ替えはまだ実装しない。
- プレビューの工程編集・参加資格は既存のサービス別ブラウザ下書きを利用。実際の募集設定・公開・決済を上書きせず、従来の設定に戻れる導線を保持。サーバー側の独立した事業入会・個別申込実行との接続は未完了。

## チェックから導線を作る（2026-11-28 承認要望）
- 募集の入口を「個別サービスの申込導線（設計）」とする。独立した「入会・共通設定」タブは廃止。移行前の実設定は工程別の確認導線から参照可能。
- 初回に共通の入会手続きの有無を明示的に確定。なしの場合は共通手続きの行・個別サービス側の参照チェックを非表示にし、再設定のみ残す。設計上の事業会員制度と同じ選択を利用し、既存権限は変更しない。
- 共通入会と各サービスを独立した行で管理。最初に必要な工程をチェックして保存すると図を生成。共通入会は個別フローで参照する1工程とし、複製しない。入会済みの人に再入会を要求しない設計。各工程をクリックして編集。
- フロー図と順序リストを同一サービス内でドラッグ可能、スマホでは上下ボタン。事前決済は確定前、当日払いは確定後、予約は説明会前、開催枠選択は決済前。必須3工程（案内・申込・確定）と設計済み料金を維持。
- 設定はプレビューのブラウザ内下書き。新たな手続きの実行・公開・決済・権限付与は未接続。既存DBと公開受付は変更しない。

## UI整理の原則（2026-11-28）
- 同一画面で同じ名称・目的の設定パネルを重複させない。画面ごとの主要設定群は最大5つを目標とし、詳細は選択した時だけ開く。ヘッダー・移動ボタン・説明行は設定パネルではない。
- 設計：最初は事業構成図と作成入口のみ。対象選択後は単独の編集画面に切替、構成図に戻る。事業の概要の重複表示を撤去。コース設定は内容・対象／開催・通い方／料金・定員／欠席・振替の4群、既存保存処理を維持。
- 募集：一覧／工程チェック／選択した導線の編集を同時に積み重ねない。選択中の導線で一つの順序リストを編集・並べ替えに使用し、工程ごとの入力欄を切り替える。移行前設定は折り畳み。
- 事業設定：基本情報／呼び方／CLASS利用契約／販売・決済の4入口。選択した内容だけ表示する。既存機能を削除しない。

## 設計を事業設定の正規入口にする（2026-11-28）
- 設計の最初に「事業設定」4入口（基本情報・呼び方・CLASSの利用契約・販売決済）。基本情報は事業名のみ。ホームの設定ショートカットも同じ設計画面に移動し、別階層を作らない。
- その下に事業構成図。タイトル右端で構成変更、各サービス種の見出し右端で作成、各コース見出し右端でそのコースにクラス追加。独立した作成ボタン群は廃止。対象サービスを選ぶと単独の編集画面、戻ると設計の一覧。入会制度の有無は募集側の初回選択に一本化。
- 呼び方はサービス4項目と人・手続き4項目を1フォームに統合し一括保存。作成ボタンの例示は削除。既存ロールとサービスキーを同一の所有者スコープの原子的更新で保存する。開発プレビューはブラウザ内で確認し、本番データには保存しない。
- サイトマップ：事業一覧→事業ホーム→設計（設定4入口＋構成図）、募集（個別導線・事業の募集ページ・改善）、運営、会計。設定は設計の子画面、別の主要領域にしない。

### 作成ボタンの配置修正
- コース種別の見出し右端に「＋コース追加」「＋クラス追加」を一箇所に集約する。個別コース行の追加ボタンを廃止。コース1件ならそのコースに追加、複数なら追加先を選択。0件なら先にコースを作成する（クラス追加は無効）。

## 募集フローの横型表示（2026-11-28）
- 募集導線は一覧・編集の双方で、工程を左から右へ矢印でつないだ横一列の図に統一する。長い導線は図の中だけ横スクロール。
- 工程そのものをドラッグして同一導線内で並べ替える。選択した工程の左右移動ボタンも用意する。工程を押すとその下の編集欄を切り替える。縦型順序リストを別途表示しない。
- 保存済みの順序検証・ブラウザ内の下書きと本番未接続の方針は維持する。

## 募集工程の具体的設定（2026-11-28）
- 横型のフロー図を維持。各工程の編集は自由文だけにせず、目的別の選択・入力欄を使用する。申込項目は既存の applicationFields に対応し、必須／任意／非表示を選ぶ。氏名・メールは必須、未成年向けの保護者情報は必須。コースの成人・未成年設定を引き継ぐ。確認用のフォームは送信しない。
- テスト申込・テスト実施・合否判定を独立工程とし、合否判定は手動または点数基準を設定。説明会／テストの予約、実施場所・方法、運営者の確認、規約、開催枠、決済方法、確定通知を構造化。料金と開催枠を設計から参照する。
- 募集ページが先頭。予約は実施前、テストは合否・承認前、申込・承認・同意・開催枠選択・テスト結果は事前決済前、確定は必要工程の後。当日払いは確定後。既存のドラッグ・左右移動・保存に同じ検証を適用し、不正な順序は保存しない。テスト後に本申込する導線と、申込後にテストする導線の双方を許容。
- 工程設定はブラウザ内の下書き。通知・予約・合否・決済等を実際に実行するサーバー側フローとの接続は未完了。個人情報は収集しない。既存設定は変更しない。
